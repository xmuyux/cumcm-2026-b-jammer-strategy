# B 题：机器狗自动搜索定位与清除（程序与离线仿真）

## 文件

| 文件 | 作用 |
| --- | --- |
| `arena.py` | 题面规则常量、随机案例生成、离线模拟器（同一套物理与计时规则） |
| `geometry.py` | 凸多边形裁剪、最小包围圆、射线交会 |
| `strategy.py` | 搜索 / 定位 / 清除策略 |
| `robot.py` | 官方接口的 HTTP+JSON 客户端（幂等重试、accepted 校验、计时） |
| `mock_server.py` | 本地模拟器（127.0.0.1:2026，协议与官方一致） |
| `run.py` | 入口：离线批量评测 / 连官方模拟器 / 起本地模拟器 |
| `experiment.py` | 多套参数对比 |
| `lattice_design.py` | 搜索格点设计与"包围保证"校验 |
| `debug_case.py` | 单案例逐频道复盘（观测 vs 真值） |

## 常用命令

```bash
py -3 run.py --cases 50                        # 问题3条件（全向）：50 个随机案例
py -3 run.py --cases 50 --directional 5 --mode mixed   # 问题4条件（混合）：5 个定向
py -3 run.py --cases 1 --verbose               # 看单局完整过程
py -3 run.py --serve --seed 5                  # 起本地模拟器（端口 2026）
py -3 run.py --real --robot-id <参赛队号>       # 连官方模拟器跑一局
```

## 策略要点（论文可直接用）

1. **定位区域**：示向度误差 ≤1°，所以某频道所有可能的源位置 = 各示向度楔形交集 ∩ 圆域 ∩ 各检测点
   1500 m 内圆盘，是凸集，真实源必在其中。用凸多边形裁剪得到它，取最小包围圆（问题 1 的
   "定位区域直径"）。
2. **清除判据**：包围圆半径 ≤ 20 m 时，站在其圆心 `/clear` 必然成功——这就是问题 1 结论的工程化用法。
   实测中取 17 m 留余量，配一套小范围清除点阵兜底。
3. **搜索保证**：
   - 问题 3（全向）：取半径 1200 m 的六边形 + 圆心共 7 个检测点，覆盖半径 967 m < 1000 m
     的最小有效接收半径，因此任何未清除干扰源必定被扫到。
   - 问题 4（含定向）：定向源只在 ±90° 半平面内辐射，仅"覆盖"不够，还需要**包围**：一个点 q
     的周围 1000 m 内要有各方向的检测点。取间距 900 m 的三角格点（31 个点）即可保证
     （数值校验最大角间隙 139° < 180°）。
4. **省时技巧**：已定位的频道不再重复测；格点若离已知区域 >1500 m 则必然测不到、直接跳过；
   沿途顺路（绕行 ≤500 m）就先把已定位的源清掉；定向源定位用加权最小二乘交会，波束近乎平行时
   改做侧向探测。

## 实测性能（离线仿真，每档 40–60 个随机案例）

| 条件 | 全部清除率 | 总时间均值 | 平均单源时间 |
| --- | --- | --- | --- |
| 问题 3（全向 10–16 个） | 100% | 4178 s | 332 s |
| 问题 4（2 个定向） | 100% | 9215 s | 741 s |
| 问题 4（5 个定向） | 100% | 9513 s | 765 s |
| 问题 4（8 个定向） | 100% | 9811 s | 788 s |
| 问题 4（12 个定向） | 100% | 10150 s | 820 s |

虚拟时间上限为 360000 s，现实程序运行时间上限 1200 s（一局约 600–1500 次请求，实际耗时数秒）。

## 接官方模拟器的步骤

1. 百度网盘下载模拟器：`https://pan.baidu.com/s/1P1yfVjY0RufU93XOdzhOLw?pwd=2026`，提取码 `2026`，
   解压后直接运行（绿色软件，别单独搬动目录内的数据文件）。
2. 首次运行用参赛队号 + 队员 1 姓名 + 手机号注册，设置密码（12–64 位，含字母和数字）。
3. 先做「问题 3 演练测试」：倒计时结束、界面显示接口就绪后再运行
   `py -3 run.py --real --robot-id <参赛队号>`。演练不限次数，且会告知本局真实干扰源总数，
   用它核对程序的清除个数。
4. 确认无误后做 3 次问题 3 正式测试、3 次问题 4 正式测试（问题 4 用 `--mode mixed` 的同一份程序），
   记录案例编码并导出日志放进支撑材料。
5. 截止：北京时间 2026-09-13 17:30 之后不能开新测试，建议 15:30 前完成全部正式测试。

## 注意

- 程序用自带的 Python 运行即可（本机 PATH 里没有 python，用完整路径或先装 Python 3.12）。
- 每局日志会写到 `robot_log.jsonl`（题目要求自行记录指令序列与响应）。
- `--real` 默认等待接口开放最多 150 s；`/enter` 失败会复用同一个 request_id 重试。
